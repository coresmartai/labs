# Installing cloudflared (do this before class)

Your laptop has no public address. A tunnel gives it one: `cloudflared` dials **out**
to Cloudflare, and Cloudflare hands you a public HTTPS URL that forwards back to your
`localhost:8000`. No router config, no firewall rules, no account.

Do this **before** the session - not during it.

---

## Install

### Windows

```bash
winget install --id Cloudflare.cloudflared
```

No winget? Download `cloudflared-windows-amd64.exe` from Cloudflare's GitHub releases,
rename it to `cloudflared.exe`, and put it somewhere on your `PATH`.

### macOS

```bash
brew install cloudflared
```

### Linux (Debian / Ubuntu)

```bash
sudo apt install ./cloudflared-linux-amd64.deb
```

Download that `.deb` from Cloudflare's releases page first. Other distros: grab the
matching binary, `chmod +x`, move it onto your `PATH`.

---

## Verify

```bash
cloudflared --version
```

If that prints a version, you are done. If the shell says "command not found", the
binary is not on your `PATH` - reopen your terminal first, since installers often only
update `PATH` for new shells.

---

## Test it once, now

Two terminals. First, something to serve:

```bash
python -m http.server 8000
```

Second, the tunnel:

```bash
cloudflared tunnel --url http://localhost:8000
```

It prints a banner with a URL like `https://random-words-here.trycloudflare.com`.
Open it in a browser - you should see the directory listing from your own machine.
Stop both with Ctrl-C.

**If that worked, you are ready for the session.** If it did not, sort it out now:
see Troubleshooting below.

---

## What to expect during the session

- **The URL changes every time you restart the tunnel.** Free "quick tunnels" are
  ephemeral. This is why your card is generated by a script rather than typed by hand -
  re-run the tunnel, update one setting, re-publish.
- **Ctrl-C kills your public address.** Leave the tunnel terminal alone for the whole
  session.
- **Sleep kills it too.** Disable sleep before class. This is the single most common
  reason someone vanishes from the mesh.
- **Quick tunnels cap at 200 concurrent requests** and are explicitly test-grade. Fine
  for a class; do not build anything real on one.

---

## Troubleshooting

| Symptom | Fix |
|---|---|
| `command not found` after installing | Open a new terminal; installers update `PATH` only for new shells |
| `failed to request quick tunnel` | Usually transient - retry. If it persists, your network may block it; try a phone hotspot |
| Quick tunnel refuses to start | Delete or rename `~/.cloudflared/config.yaml` - quick tunnels are unsupported when a config file exists |
| Tunnel starts, URL 502s | Your app is not running, or is on a different port than the one you tunnelled |
| Corporate laptop blocks it | Try a hotspot, or ask about the deploy option in [`SESSION.md`](SESSION.md) |

## If tunnels are impossible on your machine

You can still do everything in **solo mode** - the whole build runs on localhost with
local dummy peers, no tunnel and no classmates required. See [`SESSION.md`](SESSION.md).
You will miss the live cross-machine moment, not the material.
